# DevFlow v2 需求文档（PRD）

**版本：** v2
**日期：** 2026-11-06
**状态：** 待评审
**上一版：** `docs/specs/2026-11-05-devflow-design.md`（v1 已完成并通过验收）

---

## 1. 背景与目标

### 1.1 现状

v1 已经能在浏览器里完成一个最小闭环：选工作区 → 对话 → agent 调用 `list` / `read` / `search` / `write_patch` 四个工具 → 单文件 diff 审批 → 终端执行命令 → 刷新恢复。它可以演示，但离"真正能替用户干活"还差六件事：

| 现状 | 用户感受到的问题 |
|---|---|
| 没有任务规划，agent 想到哪做到哪 | 长任务不知道它要做什么、做到哪一步了 |
| `search` 只是递归文本正则，深度 ≤ 4、最多扫 200 个文件、返回 100 条 | 在稍大的工程里找不到代码，只能盲读文件 |
| 只能对已存在的单个文件做唯一文本替换 | 不能新建文件、不能删除文件、不能整文件重写、不能一次改多个文件 |
| agent 不能执行命令 | 改完代码不能自己跑测试，错了也不会自己修 |
| 上下文超过上限只做简单截断 | 长会话丢目标、丢决策，越聊越笨 |
| 单标签编辑器、无权限模式、无检查点、不能停止 | 改错难回退，agent 什么时候能写文件不透明 |

v2 的目标就是补齐这六件事，让 DevFlow 从"能演示的 agent"变成"能独立完成一个中小型开发任务的 agent"。

### 1.2 目标用户与核心任务

**用户**：在浏览器里维护一个真实代码仓库的开发者（当前主要用户是项目作者本人，用于日常开发和面试演示）。

**核心任务**：用一段自然语言描述一个开发任务，agent 自主完成「理解代码 → 制定计划 → 修改多个文件 → 运行验证 → 修复失败 → 汇报结果」，用户只需在关键变更和命令执行上做审批。

**完成条件**：任务结束时，用户能看到（1）一份逐项完成的计划，（2）一份列明改动文件的变更清单，（3）一次成功的验证命令输出。三者齐备才算任务完成，缺一即视为未完成并进入失败/继续流程。

### 1.3 v2 的成功标准

- 用户在本地目录会话里，用一段话让 agent 完成一个需要 ≥ 2 个文件改动、且需要跑一次验证命令的任务，全程只需审批、不需要手动补代码。
- 在 20 轮以上的连续会话里，agent 仍能引用会话早期的目标和已改动文件。
- 用户可以在任何时刻停止生成、切换权限模式、回滚到本次任务开始前。

## 2. 范围

### 2.1 P0（v2 必须完成）

| 编号 | 能力 | 最低可接受行为 |
|---|---|---|
| FR-01 | 任务规划与可见待办 | 多步任务先给出 3–8 项计划，执行中逐项更新状态 |
| FR-02 | 代码库地图与检索 | 自动维护项目地图；支持按文件名、符号名、文本三种方式检索并返回路径+行号 |
| FR-03 | 多文件编辑与文件管理 | 支持新建、整文件写入、删除、单次提案多个文件；按文件审批，整批原子生效 |
| FR-04 | 验证闭环 | agent 可发起受控命令，读取退出码与输出；失败后最多自动修复 2 轮 |
| FR-05 | 上下文管理 | 分层 token 预算 + 结构化历史摘要 + `DEVFLOW.md` 项目规则注入 |
| FR-06 | 体验与安全 | 多标签编辑器、三档权限模式、run 级检查点与回滚、停止生成、会话变更清单 |

### 2.2 P1（P0 完成后可做，不阻塞验收）

- 用户可编辑 agent 给出的计划项（增删/改顺序）。
- 单次补丁级撤销（不用回滚整个检查点）。
- 从命令输出自动跳转到出错文件的具体行。
- 会话级用量与成本展示（token / 步数 / 命令耗时）。
- 同一条命令在会话内"记住批准"，减少重复审批。

### 2.3 明确不做（v2 范围外）

- Docker 沙箱恢复、云端部署、多用户与权限体系。
- 向量检索 / embedding 索引（先用符号 + 文本索引，见 7.1）。
- Git 自动提交、自动建 PR、代码评审机器人。
- 插件系统、自定义工具、多 agent 协作。
- 内置网页预览、浏览器自动化。
- 移动端适配。
- 删除或替换现有 3 个 demo 仓库（保留，作为零配置演示入口）。

## 3. 产品模型与核心流程

### 3.1 对象与状态

| 对象 | 说明 | 关键状态 |
|---|---|---|
| 会话 Session | 一个工作区（demo 仓库或用户本地目录）+ 一段连续对话 | 空闲 / 运行中 / 已停止 / 已取消 |
| 任务计划 Plan | 一次 run 内 agent 给出的步骤清单 | 未生成 / 执行中 / 已完成 / 部分失败 / 已取消 |
| 计划项 PlanItem | 计划中的一步 | 待办 / 进行中 / 完成 / 失败 / 跳过 |
| 变更批次 ChangeSet | 一次工具调用产生的 1..N 个文件变更 | 待审批 / 部分审批 / 已生效 / 已拒绝 / 已过期 / 冲突 |
| 命令执行 CommandRun | 一次受控 shell 命令 | 待审批 / 运行中 / 成功 / 失败 / 超时 / 已取消 |
| 检查点 Checkpoint | 一次 run 开始前的工作区快照 | 可回滚 / 已回滚 / 已淘汰 |

### 3.2 核心流程

```
用户提出任务
   ↓
[理解] 读取项目地图 / 检索相关文件（FR-02）
   ↓
[规划] 输出 3–8 项计划（FR-01）
   ↓
[执行] 逐项调用工具：读 / 检索 / 改文件（FR-03）
   ↓            └─ 每次文件变更 → 用户审批 → 原子落盘
[验证] 运行命令（FR-04）→ 成功 → 勾选计划项
   ↓                      └─ 失败 → 回灌错误 → 修复 ≤ 2 轮
[汇报] 变更清单 + 验证结果 + 未完成项
```

失败与恢复路径：

- 用户拒绝变更 → agent 重新规划该步骤，不重复提交相同补丁。
- 命令失败且自动修复 2 轮仍失败 → 停止自动修复，输出失败原因与建议，等待用户决定。
- 用户停止生成 → 当前 run 立即结束，未审批变更失效，已落盘变更保留并进入变更清单。
- 用户回滚检查点 → 工作区文件恢复到该 run 之前，后续检查点失效。

### 3.3 布局调整

在 v1 三栏布局上增量调整：

- 中间区域：Monaco 从单文件改为**多标签**，标签栏显示文件名、未保存圆点、agent 修改标记。
- 右侧对话面板：新增**计划卡片**（顶部）、**变更清单入口**（底部）。
- 顶栏：新增**权限模式下拉**（只读 / 需审批 / 自动接受）、**检查点入口**。
- 生成中：发送按钮变为**停止**按钮。

## 4. 功能需求

### FR-01 任务规划与可见待办

**目的**：让长任务的过程对用户可见、可判断、可打断。

**触发**：用户发送的请求满足以下任一条件时生成计划——预计涉及 ≥ 2 个文件，或包含"新增/重构/修复/实现/迁移"等动作，或用户在消息中要求"先给计划"。单文件单步的小改动（如改一行文案）不生成计划，直接执行。

**处理规则**：

- 计划由 agent 在第一次工具调用之前输出，项数 3–8，每项是一句可验证的动作描述（如"在 `src/routes.js` 新增 GET /healthz"），不写"分析代码"这类无法验证的项。
- 每项必须能对应到至少一个工具结果或一次命令结果作为完成证据；没有证据的项不得标记完成。
- 执行过程中同一时间只有一项处于"进行中"；完成后立刻更新为"完成"，失败则标记"失败"并记录原因。
- 计划允许在执行中调整：新增、删除、重排都必须先输出一句调整原因，再更新卡片；调整后的计划仍需满足 3–8 项。
- 所有计划项结束（完成/失败/跳过）后，agent 输出总结：完成项、失败项、未完成原因。

**结果与状态变化**：计划卡片常驻在对话面板顶部，刷新页面后随会话历史恢复。计划状态与会话记录一起持久化，用户重新进入会话仍能看到上次的计划与每项结果。

**异常**：

- 模型未给出计划（直接开始调工具）：不阻塞执行，前端显示"本次未生成计划"，任务结束后补一份结果摘要。
- 计划项连续两次失败：停止该项的自动重试，把该项标记为失败并询问用户"继续下一项 / 调整计划 / 停止"。
- 用户在计划执行中途发送新消息：保留已完成项，剩余项标记为"跳过"，以新消息为准重新规划。

### FR-02 代码库地图与检索

**目的**：让 agent 先定位再读文件，减少盲目读取与无效 token 消耗。

**触发**：进入会话后自动建立项目地图；每次文件变更后增量更新。agent 在需要定位代码时调用检索工具；用户也可在文件树顶部搜索框直接检索（复用同一套结果）。

**处理规则**：

- **项目地图**：列出工作区内所有可编辑文件，并为代码文件提取顶层符号（类、函数、组件、路由定义、导出常量），形成"文件 → 符号 + 行号"的索引。忽略 `node_modules`、`dist`、`build`、`.git`、虚拟环境、缓存目录等（沿用 v1 忽略清单）。
- **三种检索方式**：
  1. 文件名检索：按片段模糊匹配路径，返回全部命中路径。
  2. 符号检索：按符号名精确或前缀匹配，返回 `路径:行号: 符号签名`。
  3. 文本检索：按文本或正则匹配，返回 `路径:行号: 该行内容`（沿用 v1 能力，但解除深度 4 层限制）。
- 检索结果单次最多返回 50 条，超出时标注"已截断，可缩小范围或翻页"；agent 可通过 `offset` 继续取下一页。
- 结果必须带路径和行号，且路径为工作区相对路径；不允许返回工作区外的路径。
- 文件变更（写入、删除、外部编辑器保存）后 1 次工具调用内索引必须反映最新内容；索引未就绪时检索退化为实时扫描，并在结果中标注"索引构建中"。
- 地图与索引只在会话内有效，不跨会话共享；用户本地目录中的敏感文件不进入摘要输出。

**结果与状态变化**：项目地图作为系统上下文的一部分注入，用户不可见；检索结果以工具卡片展示（命中数、扫描文件数、是否截断）。

**异常**：

- 工作区文件数超过 1 万个：只索引前 1 万个（按路径排序），并在工具卡片提示"索引已限量"。
- 文件读取失败（权限/编码/超大）：跳过该文件，结果中标注跳过数量，不中断检索。
- 索引构建失败：降级为 v1 的实时递归扫描，功能可用但更慢。

**验收目标**（初版目标，实施阶段可调整）：1 万文件以内的项目，首次索引在用户发出第一条消息前完成；单次检索返回 ≤ 2 秒。

### FR-03 多文件编辑与文件管理

**目的**：从"只能改一行"升级到"能完成真实开发任务"。

**触发**：agent 判断当前任务需要新建文件、整文件重写、删除文件，或一次改动涉及多个文件时。

**能力与规则**：

| 操作 | 行为 | 审批要求 |
|---|---|---|
| 新建文件 | 提交完整文件内容预览；目标路径已存在时转为"整文件覆盖"并明确标注 | 需审批 |
| 整文件写入 | 提交 before/after 完整内容与 diff | 需审批 |
| 精确替换 | 沿用 v1：`search` 必须唯一匹配，0 次或多次都拒绝 | 需审批 |
| 删除文件 | 展示文件大小与最后修改时间，删除前二次确认 | **所有权限模式都必须确认** |
| 批量变更 | 一次提案包含 1..N 个文件，逐个文件展示 diff | 可逐文件接受/拒绝，也可整批接受 |

**批次规则**：

- 一个变更批次采用**原子生效**：只要批次内任一文件落盘失败（路径冲突、权限、文件在审批期间被外部修改），整批都不落盘，已写入的部分回滚，批次状态置为"冲突/失败"并说明原因。
- 审批期间文件内容发生变化：该文件标记为"冲突"，不得静默覆盖；agent 需要重新读取后重新提案。
- 批次审批超时（默认 120 秒，沿用 v1）视为拒绝，卡片标记"已过期"，agent 不得自动重试相同补丁。
- 用户拒绝某个文件但接受其他文件：仅接受的子集生效；被拒文件作为失败结果回灌给 agent，要求换方案。
- 单次批次最多 10 个文件；超过时拆分为多个批次依次提交。
- 二进制文件、超过 1 MB 的文本文件不允许由 agent 直接写入；应提示用户手动处理。

**结果与状态变化**：接受后文件立即落盘，已打开的多标签编辑器自动刷新（若有未保存内容，见 FR-06 冲突规则），文件树同步更新，变更清单新增记录。

**异常**：

- 目标路径在工作区外：直接拒绝并提示。
- 新建文件所在目录不存在：自动创建父目录（在预览中说明）。
- 删除正在被编辑器打开且有未保存内容的文件：先提示用户保存或放弃，再执行删除。

### FR-04 验证闭环

**目的**：让 agent 改完能自己验证，错了能自己修，而不是把错误丢给用户。

**触发**：

- agent 完成一组代码修改后，主动发起验证命令（若项目存在可识别的测试/构建/类型检查入口）。
- 用户明确要求"跑一下 / 启动看看 / 跑测试"。

**处理规则**：

- agent 发起命令时必须说明：命令内容、工作目录（固定为工作区根或其子目录）、预期结果（通过/输出什么）、超时时间。
- 命令在工作区内执行，禁止访问工作区外的路径；禁止提权、关机、格式化、批量删除根目录等危险命令（内置黑名单）。
- 默认超时 30 秒，agent 可申请延长到最多 120 秒；超时后终止进程并标记"超时"。
- 输出实时流式展示在工具卡片中；超长输出保留头 200 行 + 尾 200 行，中间标注截断行数。
- agent 读取退出码与输出后：
  - 退出码为 0 → 标记成功，勾选对应计划项。
  - 非 0 → 提取报错关键行，定位到文件/行号，进入修复流程。
- **自动修复上限 2 轮**：每轮必须基于新的错误输出修改；第 3 次仍失败则停止，输出"失败原因 + 已尝试的修复 + 建议"，等待用户决定。
- 修复轮次内不得重复提交完全相同的命令与补丁（复用 v1 的重复调用检测）。

**审批规则**：受权限模式控制（见 5.1）。默认"需审批"模式下，每次新命令都需用户确认；只读类命令（如 `ls`、`git status`、`cat`）可在会话内自动通过（P1）。

**结果与状态变化**：成功/失败结果写入会话历史与工具记录；变更清单中对应文件标记"已验证"或"验证失败"。

**异常**：

- 交互式命令（等待 TTY 输入，如 `npm init`、`read`）：直接拒绝并提示改用非交互参数。
- 端口被占用 / 依赖未安装：把原始错误回灌给 agent，由 agent 决定安装依赖或换方案；安装依赖属于写操作，需用户审批。
- 命令执行期间用户手动在终端输入：终端与 agent 命令互斥，agent 命令运行时用户输入排队；用户可随时点停止终止 agent 命令。

### FR-05 上下文管理

**目的**：长会话不丢失关键信息，且不因超出模型窗口而突然失忆。

**触发**：每次调用模型前计算当前上下文预算；接近上限时触发压缩。会话开始注入项目规则文件。

**分层预算**（初版建议，实施阶段可调）：

| 分区 | 占比 | 内容 |
|---|---|---|
| 固定层 | 10% | 系统提示、当前模型、项目规则（`DEVFLOW.md`） |
| 地图层 | 10% | 项目地图摘要（文件树 + 符号数量，非全文） |
| 摘要层 | 20% | 历史对话的结构化摘要 |
| 工作层 | 60% | 当前任务计划、最近对话、最近工具结果、待审批变更 |

**处理规则**：

- 历史超过摘要层预算时生成结构化摘要，必须包含：用户目标、已改动文件清单、关键决策与约束、失败与已尝试方案、未完成事项、最近一次验证结果。
- 摘要生成后，保留最近 3 条用户消息与最近 1 轮工具结果原文；更早的原文可丢弃。
- 压缩发生时前端显示一条系统提示"已压缩早期上下文（保留目标与未完成项）"，用户可展开查看摘要内容。
- 项目规则文件 `DEVFLOW.md` 位于工作区根目录：存在时自动读取并注入固定层；用户可在编辑器中创建/修改。规则内容与系统提示冲突时，以规则文件为准（安全规则除外）。
- 规则文件超过 2000 行只取前 2000 行并提示。
- token 估算允许 ±20% 误差；预算判断以估算值为准，不追求精确计费。

**结果与状态变化**：压缩不改变会话历史原文（持久化保留全部消息），只影响下一次发给模型的内容；用户刷新后仍能看到完整历史。

**异常**：

- 摘要生成失败（模型报错/超时）：降级为 v1 截断策略，并在对话中提示"上下文压缩失败，已截断早期消息"。
- 单条工具结果过大（如整文件读取）：先按工具级上限截断，再进入上下文；不允许单条结果占用工作层 30% 以上。
- 规则文件包含疑似密钥：注入前打码并在提示中告知用户（不阻断）。

### FR-06 体验与安全

**目的**：把"agent 能改代码"这件事变得可控、可回退、可中断。

#### 6.1 多标签编辑器

- 文件树点击文件在中间区域新开标签；同一文件只保留一个标签；标签显示文件名、未保存圆点、被 agent 修改标记（未查看时高亮）。
- 标签可关闭；关闭有未保存内容的标签需确认（保存/放弃/取消）。
- 标签数量上限 10 个，超出时关闭最久未使用的非活动标签（有未保存内容的不自动关闭）。
- agent 修改已打开且**无未保存内容**的文件：自动刷新内容，标签短暂高亮。
- agent 修改已打开且**有未保存内容**的文件：不自动覆盖，标签标记"冲突"，提供"查看差异 / 保留我的 / 使用 agent 版本"三个操作。
- 标签状态随会话保存在前端；刷新页面后恢复上次打开的标签与文件（不要求恢复未保存的临时编辑，未保存内容需在刷新前提示）。

#### 6.2 权限模式

三档，顶栏下拉切换，按会话记忆：

| 模式 | 文件写入/新建 | 删除文件 | 命令执行 | 适用场景 |
|---|---|---|---|---|
| 只读 | 拒绝（agent 提示当前为只读） | 拒绝 | 拒绝 | 只想让 agent 分析代码 |
| 需审批（默认） | 每次变更弹审批 | 二次确认 | 每次命令弹审批 | 日常使用 |
| 自动接受 | 自动生效，变更清单记录 | 仍需二次确认 | 仍需审批 | 信任 agent 的批量重构 |

规则：

- 模式切换立即生效，不影响正在等待审批的卡片（等待中的卡片仍按发起时的模式处理）。
- 只读模式下 agent 仍可读文件、检索、生成计划；写入与命令尝试会返回失败结果并说明原因，agent 不得反复重试。
- 自动接受模式只自动接受**编辑类**操作；删除与命令永远需要确认。

#### 6.3 检查点与回滚

- 每次 run 开始前自动创建检查点：记录本次 run 可能影响的所有文件的原内容（只存被改动的文件，不存全仓库）。
- 检查点入口在顶栏，展示时间、用户消息摘要、涉及文件数；可回滚到任意检查点。
- 回滚 = 把该检查点之后所有变更的文件恢复到检查点时的内容；回滚本身也需要二次确认，并提示"回滚会丢弃这之后的所有改动"。
- 一个会话最多保留 50 个检查点，超出淘汰最旧的；被淘汰的检查点不可回滚。
- 回滚后，当前打开的标签自动刷新；有未保存内容的标签先提示。
- 回滚会同时把会话中该时间点之后的消息标记为"已回滚"（保留展示，置灰），避免用户误以为改动仍存在。

**异常**：检查点创建失败（磁盘不足/权限）→ run 不允许开始，提示用户处理后重试；不允许在没有检查点的情况下执行写操作。

#### 6.4 停止生成

- 生成中发送按钮变为"停止"；点击后 1 秒内结束当前 run。
- 停止后：已输出的文本保留并标记"已停止"；未审批的变更卡片失效（标记"已取消"）；已落盘变更保留并进入变更清单；正在运行的命令被终止。
- 停止后可立即继续对话，不需要新建会话。

#### 6.5 变更清单

- 右侧对话面板底部提供"本次会话变更"入口，列出所有被 agent 改动的文件：路径、新增/删除行数、状态（待审批/已生效/已拒绝/已回滚/验证失败）。
- 点击文件打开对应 diff（与审批卡片同一套展示）。
- 变更清单按时间倒序，刷新后从会话记录恢复。

### FR-07 既有能力保留

以下能力不得在 v2 中被削弱：

- 本地目录会话（用户直接指定本机目录）与 3 个内置 demo 仓库（保留，作为零配置演示入口）。
- 自定义模型 Provider 管理（增删改、测试连通性、启用切换）。
- SSE 流式对话、工具卡片、Diff 审批、xterm 终端、F5 刷新恢复、JWT 会话归属校验。

## 5. 共享规则

### 5.1 权限矩阵

| 操作 | 只读 | 需审批 | 自动接受 |
|---|---|---|---|
| 读文件 / 检索 / 列目录 | 允许 | 允许 | 允许 |
| 生成计划 / 输出文本 | 允许 | 允许 | 允许 |
| 新建 / 写入 / 精确替换 | 拒绝 | 审批 | 自动 |
| 删除文件 | 拒绝 | 二次确认 | 二次确认 |
| 执行命令 | 拒绝 | 审批 | 审批（只读命令可自动，P1） |
| 回滚检查点 | 二次确认 | 二次确认 | 二次确认 |

### 5.2 审批与超时

- 变更批次与命令审批默认超时 120 秒；超时视为拒绝/取消。
- 同一批次内不得混入删除操作与非删除操作（删除单独成批，便于二次确认）。
- 被拒绝的变更必须作为失败结果回灌模型，且同一 run 内不得重复提交完全相同的变更。

### 5.3 工具结果回灌上限

| 结果类型 | 单条上限 |
|---|---|
| 文件读取 | 2000 行（沿用 v1） |
| 检索结果 | 50 条/页 |
| 命令输出 | 头 200 行 + 尾 200 行 |
| 项目地图 | 仅注入摘要，不注入全文 |

### 5.4 运行上限

- 单次 run 最多 25 步（沿用 v1，可配置）；达到上限输出"已达到步数上限"并保留进度。
- 自动修复最多 2 轮；同一工具 + 相同入参连续 3 次判定为卡住（沿用 v1），注入提示。
- 单次 run 最多执行 10 条命令；超过需用户明确同意继续。

### 5.5 安全边界

- 所有文件路径、命令工作目录必须落在当前工作区内；本地目录会话同样校验。
- 命令黑名单至少覆盖：删除根目录/工作区外路径、格式化磁盘、提权、关机重启、修改系统配置。
- 会话删除时只清理 DevFlow 自己创建的工作区；用户本地目录永不删除。

## 6. 验收场景

以下场景是 v2 的验收依据，全部在浏览器中按序走通即视为通过。

**S1 多文件任务闭环**
在某个 demo 仓库会话中要求："给应用加一个 `/healthz` 接口，并补一个能跑通的检查脚本，最后跑给我看。"
预期：看到 3–8 项计划 → 检索定位入口文件 → 提交包含 2 个文件的变更批次（新建脚本 + 修改入口）→ 审批后原子生效 → 发起命令 → 输出成功 → 计划项全部勾选 → 给出变更清单与验证结果。

**S2 检索定位**
在一个稍大的工作区提问："登录相关逻辑在哪个文件？"
预期：agent 使用符号/文本检索直接给出路径与行号，不需要先盲目读取多个文件；工具卡片显示命中数。

**S3 新建与删除**
要求："新建 `src/utils/format.js` 写一个格式化函数，并删掉旧的 `src/legacy.js`。"
预期：新建文件展示完整预览；删除单独成批并二次确认；接受后文件树同步；未确认删除则删除不生效。

**S4 长会话上下文**
连续对话 20 轮以上，中途穿插多个文件改动。
预期：agent 仍能引用最早的目标与已改文件；出现"已压缩早期上下文"提示；不出现上下文超限报错。

**S5 权限模式**
切到只读模式后要求 agent 改文件；再切到自动接受模式做同样的改动，并要求跑命令。
预期：只读模式下 agent 明确说明无法写入且不反复重试；自动接受模式下编辑不再弹审批、命令仍需审批。

**S6 检查点回滚**
让 agent 做一次会产生错误的改动，然后回滚到该 run 之前的检查点。
预期：回滚二次确认后，相关文件恢复到改动前；编辑器自动刷新；终端命令验证内容已还原；会话中该时间点之后的消息置灰标记"已回滚"。

**S7 停止生成**
在 agent 连续执行多步任务时点击停止。
预期：1 秒内停止；已输出内容保留并标记"已停止"；未审批变更标记"已取消"；可以立即发送下一条消息。

**S8 项目规则**
在工作区根目录创建 `DEVFLOW.md`，写明"新增文件一律使用 TypeScript"。
预期：下一次任务中 agent 遵守该规则；删除规则文件后不再生效。

**必过的回归检查**：v1 的 5 个验收场景（会话创建、SSE 流式工具调用、diff 审批、终端执行、F5 恢复）仍然全部通过；3 个 demo 仓库仍可创建会话并正常使用。

## 7. 未决问题

| 编号 | 问题 | 当前默认方案 | 影响 |
|---|---|---|---|
| Q1 | 检索是否需要向量/embedding | 不做，先用符号 + 文本索引 | 影响检索质量上限；后续可作为 v3 |
| Q2 | 检查点快照存哪里 | 工作区外的本地快照目录，按会话隔离 | 影响磁盘占用与回滚速度 |
| Q3 | 自动修复是否允许执行写操作命令（如安装依赖） | 不允许自动执行，必须审批 | 影响修复成功率 |
| Q4 | 命令白名单/黑名单的具体清单 | 先内置最小黑名单 + 只读命令白名单 | 影响安全与审批频率 |
| Q5 | 计划项是否需要持久化到数据库 | 需要，随会话恢复 | 影响刷新恢复的实现范围 |
